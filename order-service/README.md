# Order Service

## Ответственность

Будущий владелец жизненного цикла заказа и координации резервирования в рамках своей предметной области.

## Не должен делать

- не является источником истины для доступного товарного остатка;
- не доставляет уведомления напрямую;
- не раскрывает внутренние модели другим сервисам;
- не заменяет API Gateway как публичную границу.

## Предполагаемые входные интерфейсы

Запросы, поступающие через API Gateway, и внутренние gRPC-вызовы после появления контрактов. Окончательные HTTP- и gRPC-методы пока не определены.

## Предполагаемые исходящие зависимости

Внутренний вызов `inventory-service` для операций с резервированием и будущая публикация доменных событий через outbox. Зависимости Kafka, PostgreSQL и Redis пока не подключены.

## Предполагаемые данные

Заказы, состояния обработки, ключи идемпотентности и будущие записи outbox. Схема, миграции и хранилище отсутствуют.

## Статус

**Not implemented.**
