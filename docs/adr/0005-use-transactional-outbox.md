# ADR-0005: Использовать Transactional Outbox

- Статус: proposed
- Дата: 2026-07-19

## Контекст

Будущие сервисы должны согласованно сохранять доменное состояние и публиковать события без ложного обещания распределённой транзакции.

## Решение

Планировать transactional outbox: запись состояния и записи outbox происходят в одной локальной транзакции, публикация выполняется отдельным процессом позже.

## Последствия

### Положительные последствия

- снижается риск потери события после изменения данных;
- появляется явная точка для повторной доставки.

### Отрицательные последствия

- понадобятся дедупликация, мониторинг и очистка outbox.

## Альтернативы

- прямая публикация события после commit;
- распределённая транзакция между БД и брокером.
