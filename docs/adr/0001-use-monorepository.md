# ADR-0001: Использовать монорепозиторий

- Статус: proposed
- Дата: 2026-07-19

## Контекст

Учебному проекту нужны общие контракты, документация и согласованное развитие нескольких сервисов.

## Решение

Хранить сервисы, контракты, документацию и будущую инфраструктуру в одном репозитории как учебную структуру. Каждый будущий сервис сохраняет логические границы владения кодом и данными; взаимодействие между ними будет происходить через контракты, а не через внутренности соседней папки или прямой доступ к чужому хранилищу.

## Последствия

### Положительные последствия

- единая история архитектурных решений и контрактов;
- проще выполнять согласованные учебные изменения.

### Отрицательные последствия

- потребуются правила изоляции модулей и CI для нескольких сервисов.
- такая организация не задаёт правило для production-команды: при росте независимости сервисов может понадобиться отдельный репозиторий на сервис.

## Альтернативы

- отдельный репозиторий на сервис;
- единый модуль без выделенных границ сервисов.
