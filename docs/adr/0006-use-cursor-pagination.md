# ADR-0006: Использовать cursor pagination

- Статус: proposed
- Дата: 2026-07-19

## Контекст

Будущие списочные API должны вести себя предсказуемо при изменении данных и больших объёмах.

## Решение

Для подходящих списочных REST-эндпоинтов планировать cursor pagination вместо offset pagination.

## Последствия

### Положительные последствия

- стабильнее обход данных при вставках;
- лучше масштабируется для больших смещений.

### Отрицательные последствия

- курсоры нужно проектировать, документировать и валидировать.

## Альтернативы

- limit/offset pagination;
- выдача полного списка без пагинации.
